# V0.9.1 acceptance (current checklist)

V0.9.1 adds Halo in three versions, the Graphite, Paper and Noir templates, warning colors, tinted dock tiles, a reworked theme editor, refreshed older templates, gaming sessions, stale-sensor dimming, night dimming, performance-limit tags and an assignable tray double-click. Automated checks render pages and themes off-screen and test logic with fixtures; they do not verify behavior on the dedicated displays.

This is the one open checklist. Items still relevant from V0.7.1, V0.8.0 and V0.9.0 were carried over on 2026-11-08 (marked *from 0.x*); items about features removed since (Appearance, OpenRGB color following, uptime in the Time panel, demo mode) were dropped. The older checklists are kept as history.

Legend: **[x] user** = confirmed by the user on their hardware; **[x] live** = exercised against the user's real devices or services by an automated probe with readback; **[ ]** = not yet checked; **[!]** = failed, see the fix below.

## Version and upgrade

- [ ] `Pulsewave.exe` file/product version matches the build and the tray shows it.
- [ ] Exit the previous version first. All 12 HWiNFO mappings, the game-independent FPS slot, monitor identity and scaling, placement, telemetry settings, shortcuts, schedule, lights, weather, the Plex token and the active theme carry over (Halo and Halo Column keep their ids as Halo Lifestyle).
- [ ] If Launch with Windows was on, turn it off and on once from the new tray; the registry entry starts this `Pulsewave.exe` and no duplicate old entry remains. *(from 0.7.1)*
- [ ] Settings for removed features remain untouched in settings.json.

## Lights, schedule and display power

- [x] user: the Y70 comes back on by itself when a schedule screen-off period ends (2026-11-08).
- [!] user: the LEDs did not come back on at the end of the period (2026-11-08). Cause: the lights were last set from OpenRGB profile "1", which OpenRGB no longer lists, so every "on" attempt failed and was retried each minute. Fixed after 0.9.1 (see below).
- [!] user: Lights page → Open OpenRGB did nothing useful (2026-11-08). Cause: the button could stop at OpenRGB's background service (no window), and in the program it picked the first window titled "OpenRGB", a hidden popup menu, instead of the main window. Fixed after 0.9.1 (see below).

- [ ] Dim the HUD (Backlight) lowers the Y70's backlight and restores it at the period's end and on exit.
- [ ] One overnight run with the schedule; record its duration and conditions.
