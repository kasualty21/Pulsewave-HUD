# V0.7.0 Appearance acceptance

This checklist applies to the Appearance configuration window and its simulated preview. It is separate from the user's already verified V0.6.4 hardware acceptance. The preview uses sample values and does not claim to measure live performance or hardware behavior.

## Profile workflow

- [ ] Open Appearance from the tray and confirm the active state identifies a saved profile, built-in defaults, or a custom appearance accurately.
- [ ] Edit a control and confirm the draft is marked unapplied. Return it to its applied value and confirm the state reports that it was reverted.
- [ ] Load a saved profile and restore built-in defaults. Confirm neither changes the overlay before Apply and save.
- [ ] Save a new profile; replace an existing profile and cancel/confirm the replacement; rename a profile including a case-only rename; delete a profile and cancel/confirm deletion.
- [ ] Restart and confirm profile names, active identity and visual values persist. Confirm profiles do not change any sensor mapping, FPS source slot, display identity, startup setting, or session/export state.
- [ ] Make the settings file unwritable or otherwise provoke a save error only in a disposable isolated copy; confirm failed profile operations restore the in-memory library.

## Dashboard preview

- [ ] Open Preview current draft. Confirm it is visibly labeled simulated and shows a 1920×480 dashboard with long date/device names, CPU/GPU at 100%, full memory, high network values, temperatures and unavailable sensor placeholders.
- [ ] Adjust tint, borders, opacity, high contrast, accent preset, reactivity and performance mode; confirm the preview follows the draft without modifying the live overlay.
- [ ] For a draft source matching the applied source, confirm it shows the current applied accent without reading the source. For a different image/Auto/OpenRGB draft source, confirm it labels and shows the manual fallback instead of sampling.
- [ ] Confirm the preview makes no telemetry, file/image, wallpaper, OpenRGB or screen-capture reads.
- [ ] At the dedicated display's normal viewing distance, confirm text remains fully opaque and legible. Repeat with high contrast enabled after any transparency checks.

## Preserved behavior

- [ ] Confirm hide/restore, click-through, always-on-top, startup and monitor recovery behave as in V0.6.4.
- [ ] Confirm HWiNFO telemetry, all mapped sensors, game-independent FPS selection, alerts, session statistics and CSV export behave as in V0.6.4.
- [ ] Keep Wallpaper Engine playing underneath and confirm overlay transparency and OpenRGB following remain independent.
