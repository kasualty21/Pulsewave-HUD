# Graphite System Monitor V0.4.1 — Distance Readability (Second Pass)

A standalone C# / .NET 10 WPF hardware monitor designed for a **dedicated 8-inch, 1920 × 480 display viewed from approximately 3–4 feet away**. It displays as a transparent overlay while **Wallpaper Engine** retains control of the background. Rainmeter is not required.

This is an **interface-only patch release** built on the working V0.3 telemetry engine. It preserves the existing hardware assignments, FPS slot mapping across games, sensor discovery, session statistics, graphs, CSV export, polling, alerts, display selection, click-through and tray controls.

## V0.4.1 adjustments

- **Top clock removed:** only the large main time panel displays the clock. The header contains Graphite branding and the live sensor status instead of a second clock.
- **Larger type for the 8-inch screen:** 110 px clock, 106 px CPU/GPU utilization, 78 px memory percentage, 49 px CPU/GPU temperatures, 49 px FPS, 33 px uptime, 34 px network speeds and 23–25 px labels.
- **More space for values:** panel area grows from 374 px to 408 px tall after removing the small, redundant footer. CPU/GPU cards stay separate and historical graphs remain visible.
- **Retains all functional tools:** HWiNFO sensor discovery/mapping, per-game FPS slot mapping, 12 fields, telemetry sessions, polling, CSV export, alert colors and tray settings.
- **Compiler cleanup:** explicit `Brush` alias for WPF (`System.Windows.Media.Brush`) to resolve the CS0104 compiler error reported with V0.4.0.

## V0.4 changes

- **Large, heavier type:** 106 px CPU/GPU usage figures, 110 px clock, 78 px memory percentage, 49 px temperatures, 49 px FPS, 28–36 px secondary readings. Headings and sensor labels are higher contrast than V0.3.
- **Information hierarchy:** CPU/GPU load and temperature first, large FPS and power/fan readouts second, histories underneath. System panel emphasizes RAM, VRAM and network rates.
- **Reduced small text:** Removed redundant panel numbers and tiny decorative labels. Removed clock seconds and removed the redundant header clock. Simplified graph titles and sensor count.
- **Darkened cards by default:** More reliable contrast against both dark and bright Wallpaper Engine backgrounds. The rest of the desktop remains transparent.
- **New tray setting:** `High contrast panels (8-inch display)` can be toggled at any time and is saved to the existing settings JSON. Turning it off restores a more transparent card style.
- **Visual health indicators:** Memory percentage/bar and CPU/GPU temperatures turn amber 10 units below their existing alert thresholds and red at the thresholds. These colors do *not* enable desktop notifications; threshold notifications remain opt-in.
- **Compact VRAM:** HWiNFO values explicitly formatted as MB are shown in GB (`14,780 MB` becomes approximately `14.4 GB`). Readings formatted in another unit are preserved rather than guessed.
- **No telemetry source changes:** V0.3's per-game FPS slot matching and the 12 sensor mappings are untouched.

## Upgrade without losing settings

1. Quit your currently running V0.4 application from its system-tray menu. Do not run multiple versions simultaneously.
2. Optional but recommended: back up `%LOCALAPPDATA%\GraphiteMonitor\settings.json`.
3. Unzip V0.4.1 into a **new directory**, not over V0.4.
4. Install the .NET 10 SDK if it is not present (`winget install Microsoft.DotNet.SDK.10`).
5. Open PowerShell in the extracted V0.4.1 folder and run:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\build-win-x64.ps1"
   ```

6. Start `publish-win-x64\GraphiteMonitor.exe`.
7. Right-click the tray icon to toggle `High contrast panels (8-inch display)` or open the unchanged Sensor Manager and Telemetry windows.

The existing `%LOCALAPPDATA%\GraphiteMonitor\settings.json` is reused. A missing `HighContrastCards` setting defaults to `true`. All previous assignments and session preferences should remain intact. The session's accumulated min/max/average counters restart upon application launch, as in V0.3.

### Suggested legibility test

1. Stand **3–4 feet from the actual display**, not from a scaled screenshot on the primary monitor.
2. With a bright animated Wallpaper Engine scene, verify that CPU %, GPU %, RAM %, temperatures and FPS are immediately recognizable without leaning in.
3. Run a game and verify FPS still follows the chosen numbered HWiNFO slot when the game title changes.
4. Look for clipping with a three-digit reading (GPU `100%`, FPS above `100`, fan speed above `1000 RPM`, VRAM above `10 GB`).
5. Toggle high-contrast mode from the tray. Check text remains readable with the setting off; leave it enabled if the wallpaper is distracting.
6. Confirm Sensor Manager, Telemetry window, alerts and session CSV export still work, and that the overlay continues allowing clicks through to Wallpaper Engine / the desktop.

## Known tradeoffs

- **Font scale is currently tailored to 1920 × 480.** More size presets and alternative layouts can follow after the first physical-distance test. This release does not add arbitrary scaling controls because unconstrained font scaling would cause text overlaps in the fixed four-column dashboard.
- CPU/GPU history graphs remain a compact secondary diagnostic, not the primary readability target. Graph captions are intentionally smaller than essential values; the footer was removed to free more panel space.
- Hardware names are truncated with ellipses if the selected label is too long.
- The near-opaque panels obscure more of the wallpaper; use the tray option if the wallpaper should be more prominent.
- The main clock updates at the sensor polling frequency; seconds are not shown.
- HWiNFO Registry Gadget feeds do not expose reliable per-reading timestamps, and FPS values can be absent when no game is running. Automatic slot-based FPS matching still assumes the numbered slot is stable.

## Build verification

Source structure and `MainWindow.xaml` XML were checked; existing C# control names and the card widths/timings were inspected. **The app cannot be compiled or run under Windows in this environment**, so this is a source build for first testing on your PC, not a compiled-and-verified Windows binary. If `dotnet publish` reports a compiler error, send its first `error CS...` or `error MC...` lines.

The original user-supplied Rainmeter `AIO.ini` is still included unchanged under `Reference/Original-AIO.ini`.
